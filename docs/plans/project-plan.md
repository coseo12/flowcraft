# 3D 비주얼 워크플로우 에디터 — 프로젝트 계획서

## 1. 프로젝트 개요

### 컨셉
노드 기반으로 워크플로우를 설계하고, 실행 과정과 결과를 3D 공간에서 실시간 시각화하는 풀스택 플랫폼.

### 목적
- 포트폴리오 겸 사이드 프로젝트
- 풀스택(프론트/백) 역량을 균등하게 보여줌
- 시각적 임팩트가 강한 결과물

### 핵심 차별점
- 2D 에디터에서 워크플로우 설계 → 3D 뷰포트에서 실행 흐름 시각화
- 외부 의존성 최소화 — `npm run dev` 하나로 전체 실행
- 3D 에셋 없이 코드(프로시저럴)로 모든 시각 요소 생성

## 2. 기술 스택

| 영역 | 기술 | 선정 이유 |
|------|------|----------|
| 프레임워크 | **Next.js (App Router)** | 프론트 + API를 단일 프레임워크로 처리 |
| 2D 에디터 | **React Flow** | 노드/엣지 캔버스, 커뮤니티 활발 |
| 3D 뷰포트 | **React Three Fiber + Drei** | React 생태계 내 3D 렌더링 |
| 셰이더 | **GLSL (커스텀)** | 파티클, 포스트프로세싱 이펙트 |
| 상태 관리 | **Zustand** | 2D/3D 뷰 동기화, 경량 |
| DB | **SQLite (better-sqlite3)** | 외부 DB 서버 불필요, 파일 기반 |
| 실행 엔진 | **인메모리 DAG 엔진** | Redis/BullMQ 의존 제거 |
| 실시간 통신 | **SSE (Server-Sent Events)** | WebSocket 없이 단방향 스트리밍 |
| 언어 | **TypeScript** | 프론트/백 타입 공유 |

### 외부 의존성
- **없음** (LLM API는 선택 기능, 사용자가 본인 키 입력)

### 실행 환경
```
git clone → npm install → npm run dev → 즉시 동작
배포: Docker 단일 컨테이너
```

├── components/

│   │   ├── nodes/          # 커스텀 노드 컴포넌트

├── lib/

│   │   ├── dag.ts          # 토폴로지 정렬, 사이클 감지
│   │   ├── executor.ts     # 순차/병렬 실행
│   │   └── state.ts        # 실행 상태 머신
│   ├── db/                 # SQLite 데이터 레이어

│

    └── fonts/              # 3D 텍스트용 폰트

### 화면 레이아웃
```
┌─────────────────────────────────────────────────┐
│  상단 툴바 (실행/저장/버전/설정)                    │
├────────────┬────────────────────┬───────────────┤
│            │                    │               │
│  노드      │   2D 에디터        │  3D 뷰포트     │
│  팔레트    │   (React Flow)     │  (R3F)        │
│            │                    │               │
│  - 입력    │   노드 배치/연결    │  실행 흐름     │
│  - 처리    │                    │  시각화        │
│  - AI      │                    │               │
│  - 분기    │                    │               │
│  - 시각화  │                    │               │
│            │                    │               │
├────────────┴────────────────────┴───────────────┤
│  하단 패널 (로그 / 노드 설정 / 실행 결과)           │
└─────────────────────────────────────────────────┘
```

### 2D ↔ 3D 동기화
- Zustand 스토어로 양방향 상태 공유
- 2D에서 노드 선택 → 3D에서 해당 노드 포커스/하이라이트
- 실행 시 3D 뷰포트에서 파티클 흐름 애니메이션 시작

## 5. 3D 시각화 설계

### 모든 요소를 코드로 생성 (외부 에셋 불필요)

| 요소 | 구현 방식 |
|------|----------|
| 노드 | 기본 지오메트리(Box, Sphere) + 머티리얼 색상 |
| 연결선 | Line/Tube 지오메트리 |
| 데이터 흐름 | Points + 커스텀 GLSL 셰이더 파티클 |
| 차트 | 프로시저럴 생성 (높이/색상 매핑) |
| 텍스트 | Drei `<Text>` 컴포넌트 |
| 배경 | Drei Stars/Environment + Bloom 포스트프로세싱 |

### 시각화 모드

**1) 흐름 모드 (기본)**
- 노드가 3D 공간에 자동 배치
- 데이터가 파티클로 노드 간 이동
- 실행 중: 발광 이펙트 / 실패: 붉은 이펙트 / 완료: 녹색

**2) 결과 모드**
- 시각화 노드의 출력을 3D 씬에 렌더링
- API 응답 → 3D 차트, AI 분류 → 클러스터

**3) 히스토리 모드 (Phase 3)**
- Z축을 시간축으로 과거 실행 기록을 쌓아서 비교

## 6. DAG 실행 엔진

### 핵심 로직
- **토폴로지 정렬** — 실행 순서 결정
- **사이클 감지** — 순환 참조 방지
- **병렬 실행** — 의존성 없는 노드는 Promise.all로 동시 실행
- **상태 머신** — 각 노드: idle → running → success | error | skipped

### 실행 흐름
```
사용자가 "실행" 클릭
  → API Route에서 DAG 검증
  → 토폴로지 정렬으로 실행 순서 결정
  → 인메모리에서 순차/병렬 실행
  → SSE로 각 노드 상태 변화를 클라이언트에 스트리밍
  → 3D 뷰포트에서 실시간 시각화 업데이트
  → 완료 후 실행 기록 SQLite에 저장
```

## 7. 개발 단계

### Phase 1 — 코어 (4~6주)

**목표**: 기본 워크플로우 생성 → 실행 → 3D 시각화 파이프라인 완성

- [ ] Next.js 프로젝트 셋업, 기본 레이아웃
- [ ] React Flow 2D 에디터 — 노드 추가/삭제/연결
- [ ] 노드 5종 구현: HTTP Trigger, API Call, Script, 조건문, 로그
- [ ] DAG 실행 엔진: 토폴로지 정렬, 순차 실행, 상태 머신
- [ ] SSE 기반 실행 상태 스트리밍
- [ ] R3F 3D 뷰포트 — 노드 3D 배치, 파티클 데이터 흐름
- [ ] 2D ↔ 3D 동기화 (Zustand)
- [ ] SQLite 연동 — 워크플로우 저장/로드

### Phase 2 — 확장 (3~4주)

**목표**: 노드 확장, AI 연동, 결과 시각화

- [ ] 추가 노드: Webhook, Cron, 병렬 분기, 스위치, DB Query
- [ ] AI 노드 (LLM Prompt) — 사용자 API 키 입력 방식
- [ ] 3D 결과 시각화 노드 (차트, 클러스터)
- [ ] DAG 엔진 병렬 실행 지원
- [ ] 워크플로우 버전 관리 (스냅샷, 롤백)
- [ ] 노드 설정 패널 — 동적 폼 UI

### Phase 3 — 다듬기 (2~3주)

**목표**: 비주얼 완성도, 성능 최적화

- [ ] 커스텀 GLSL 셰이더 — 파티클 이펙트, 발광
- [ ] 포스트프로세싱 — Bloom, 색수차
- [ ] 실행 히스토리 시각화 (Z축 타임라인)
- [ ] 성능 최적화 — 인스턴싱, LOD, 디바이스별 품질 분기
- [ ] 반응형 레이아웃
- [ ] 랜딩 페이지
