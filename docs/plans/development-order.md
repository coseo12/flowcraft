# FlowCraft — 개발 순서

## Phase 1 — 코어

### Step 1. 프로젝트 초기 셋업
```
1-1. Next.js (App Router) + TypeScript 프로젝트 생성
1-2. 디렉토리 구조 세팅 (app, components, lib)
1-3. 기본 의존성 설치 (reactflow, @react-three/fiber, @react-three/drei, zustand)
1-4. ESLint, Prettier 설정
1-5. 전역 레이아웃 (layout.tsx) — 기본 구조만
```

### Step 2. 레이아웃 쉘
```
2-1. 메인 에디터 페이지 라우트 생성 (app/(editor)/page.tsx)
2-2. 리사이즈 가능한 3분할 레이아웃 구현 (팔레트 | 2D 에디터 | 3D 뷰포트)
2-3. 하단 패널 (탭: 로그 / 설정 / 결과) 쉘 구현
2-4. 상단 툴바 (로고, 워크플로우명, 저장/실행/설정 버튼) 쉘 구현
2-5. 각 패널 토글/접기 기능
```

### Step 3. Zustand 스토어 설계
```
3-1. 워크플로우 스토어 — 노드/엣지 상태 관리
3-2. 실행 스토어 — 실행 상태, 노드별 status
3-3. UI 스토어 — 선택된 노드, 패널 상태, 뷰 모드
```

### Step 4. 2D 에디터 (React Flow)
```
4-1. React Flow 캔버스 통합, 줌/팬/미니맵
4-2. 노드 팔레트 — 카테고리별 목록, 드래그 추가
4-3. 커스텀 노드 베이스 컴포넌트 — 공통 레이아웃, 핸들, 상태 표시
4-4. HTTP Trigger 노드 구현
4-5. API Call 노드 구현 + 설정 폼
4-6. Script 노드 구현 + 코드 에디터 (Monaco)
4-7. 조건문 (If/Else) 노드 구현 + true/false 출력 포트
4-8. 로그 출력 노드 구현
4-9. 노드 연결(엣지) — 타입 호환 검증, 애니메이션 점선
4-10. 우클릭 컨텍스트 메뉴 (삭제, 복사)
4-11. 하단 패널 [설정] 탭 — 선택된 노드의 설정 폼 표시
```

### Step 5. DAG 실행 엔진
```
5-1. 그래프 → DAG 변환, 사이클 감지
5-2. 토폴로지 정렬 — 실행 순서 결정
5-3. 상태 머신 구현 — idle → running → success | error | skipped
5-4. 순차 실행기 — 정렬된 순서대로 노드 실행
5-5. HTTP Trigger 핸들러 구현
5-6. API Call 핸들러 구현 (fetch + 타임아웃)
5-7. Script 핸들러 구현 (샌드박스 실행)
5-8. 조건문 핸들러 구현 (분기 로직)
5-9. 로그 핸들러 구현
5-10. 노드 간 데이터 전달 — 출력 → 다음 노드 입력
5-11. 템플릿 엔진 — {{input.field}} 치환
```

### Step 6. API + SSE
```
6-1. SQLite 설정 (better-sqlite3) + 마이그레이션
6-2. POST /api/workflows — 워크플로우 생성
6-3. GET /api/workflows — 목록 조회
6-4. GET /api/workflows/:id — 상세 조회
6-5. PUT /api/workflows/:id — 수정
6-6. DELETE /api/workflows/:id — 삭제
6-7. POST /api/workflows/:id/execute — 실행 시작
6-8. GET /api/executions/:id/events — SSE 스트리밍
6-9. GET /api/executions/:id — 실행 결과 조회
6-10. 프론트에서 SSE 수신 → 실행 스토어 업데이트
```

### Step 7. 하단 패널 연동
```
7-1. [로그] 탭 — SSE 이벤트 수신하여 실시간 로그 표시
7-2. [결과] 탭 — 선택된 노드의 입출력 데이터 JSON 뷰
7-3. 노드 상태 변화 시 2D 에디터 노드 색상/아이콘 업데이트
```

### Step 8. 3D 뷰포트
```
8-1. R3F Canvas + 기본 씬 (조명, 카메라, OrbitControls)
8-2. 배경 — Stars + Environment preset
8-3. 2D 노드 구조를 3D 좌표로 매핑하는 레이아웃 알고리즘
8-4. Node3D 컴포넌트 — 노드 타입별 지오메트리 + 머티리얼
8-5. 노드 라벨 — Drei <Text>
8-6. 엣지 3D — Line/Tube 지오메트리로 노드 간 연결선
8-7. 파티클 시스템 — 엣지를 따라 이동하는 파티클 (Points + 셰이더)
8-8. 상태 이펙트 — 실행 중: 발광, 성공: 녹색, 실패: 붉은색
```

### Step 9. 2D ↔ 3D 동기화
```
9-1. 2D에서 노드 선택 → 3D 카메라가 해당 노드로 이동
9-2. 2D에서 노드 추가/삭제 → 3D 씬 즉시 반영
9-3. 실행 시 SSE 이벤트 → 3D 파티클 흐름 + 상태 이펙트 동시 업데이트
9-4. 3D 뷰포트 ↔ 2D 에디터 뷰 전환 토글
```

### Step 10. Phase 1 마무리
```
10-1. 시나리오 1 (API 데이터 가공) 엔드투엔드 테스트
10-2. 시나리오 2 (조건 분기) 엔드투엔드 테스트
10-3. 버그 수정 + 안정화
```

## Phase 2 — 확장

### Step 11. 추가 노드
```
11-1. Webhook 노드 — API Route로 외부 요청 수신
11-2. Cron 노드 — setInterval 기반 스케줄 트리거
11-3. 병렬 노드 — 다중 출력 포트, Promise.all 실행
11-4. 스위치 노드 — 다중 조건 분기 + default 포트
11-5. DB Query 노드 — SQLite 쿼리 실행 핸들러
11-6. DAG 엔진 병렬 실행 지원 — 의존성 없는 노드 동시 실행
```

### Step 12. AI 노드
```
12-1. 설정 화면 — API 키 입력/저장 (서버 메모리 보관)
12-2. PUT/GET /api/settings 엔드포인트
12-3. LLM Prompt 노드 — 프롬프트 템플릿 에디터
12-4. LLM 호출 핸들러 — API 키 연동, 에러 처리
12-5. API 키 미설정 시 AI 노드 비활성 표시
```

### Step 13. 3D 결과 시각화
```
13-1. 3D 차트 노드 — 바 차트 (Box 지오메트리 높이 매핑)
13-2. 3D 차트 노드 — 파이 차트 (원통 분할)
13-3. 결과 모드 — 시각화 노드 출력을 3D 씬에 렌더링
13-4. 흐름 모드 ↔ 결과 모드 전환 UI
```

### Step 14. 워크플로우 관리 고도화
```
14-1. 워크플로우 목록 페이지 (또는 모달)
14-2. 버전 관리 — 저장 시 스냅샷, workflow_versions 테이블
14-3. 버전 롤백 기능
14-4. JSON 내보내기/가져오기
14-5. 노드 설정 패널 고도화 — JSON Schema 기반 동적 폼
```

### Step 15. Phase 2 마무리
```
15-1. 시나리오 3 (AI 분석) 엔드투엔드 테스트
15-2. 병렬 실행 시나리오 테스트
15-3. 버그 수정 + 안정화
```

```
17-1. 실행 히스토리 조회 API

```
18-1. 3D 인스턴싱 — 동일 지오메트리 노드 배치 최적화

## 의존성 흐름 요약

```
Step 1 (셋업)
  → Step 2 (레이아웃)
  → Step 3 (스토어)
  → Step 4 (2D 에디터) ─────────────────────┐
  → Step 5 (DAG 엔진) ──→ Step 6 (API+SSE) ──→ Step 7 (하단 패널)
                                              │
  Step 8 (3D 뷰포트) ←───────────────────────┘
  → Step 9 (2D↔3D 동기화)
  → Step 10 (Phase 1 테스트)

  → Step 11~15 (Phase 2: 확장)
  → Step 16~20 (Phase 3: 다듬기)
```

> Step 4 (2D 에디터)와 Step 5 (DAG 엔진)는 **병렬 진행 가능**
> Step 8 (3D 뷰포트)는 Step 3 (스토어) 이후 **병렬 진행 가능**
