# FlowCraft — 3D 비주얼 워크플로우 에디터 기획서

## 1. 프로젝트 정의

### 프로젝트명
**FlowCraft** — 워크플로우를 만들고(Flow), 3D로 시각화한다(Craft)

### 한 줄 소개
노드 기반 워크플로우를 설계하고, 실행 과정을 3D 공간에서 실시간으로 시각화하는 웹 플랫폼

### 배경 및 목적
기존 워크플로우 도구(n8n, Zapier)는 실행 결과를 텍스트 로그로만 보여준다.
FlowCraft는 워크플로우의 데이터 흐름을 3D 파티클 애니메이션으로 시각화하여,
**실행 과정을 직관적으로 이해**할 수 있게 한다.

### 타겟 사용자
- 워크플로우 자동화에 관심 있는 개발자
- API 연동/데이터 파이프라인을 시각적으로 확인하고 싶은 사용자
- 포트폴리오 열람자 (채용 담당자, 기술 리더)

## 2. 핵심 기능

### F1. 워크플로우 에디터 (2D)
노드를 드래그앤드롭으로 배치하고 연결하여 워크플로우를 설계한다.

| 항목 | 설명 |
|------|------|
| 노드 팔레트 | 좌측 사이드바에서 노드를 캔버스로 드래그하여 추가 |
| 노드 연결 | 노드의 출력 핸들을 다른 노드의 입력 핸들로 드래그하여 연결 |
| 노드 설정 | 노드 클릭 시 하단 패널에 설정 폼 표시 |
| 캔버스 조작 | 줌, 팬, 미니맵, 다중 선택, 삭제 |
| 유효성 검사 | 사이클 감지, 필수 설정 누락 경고 |

### F2. 워크플로우 실행
설계한 워크플로우를 서버에서 실행하고, 진행 상태를 실시간으로 전달한다.

| 항목 | 설명 |
|------|------|
| 실행 트리거 | 툴바의 "실행" 버튼 클릭 |
| 실행 방식 | DAG 기반 순차/병렬 실행 |
| 상태 전달 | SSE로 노드별 상태(대기/실행중/성공/실패) 실시간 스트리밍 |
| 실행 로그 | 하단 패널에 노드별 입출력 데이터, 소요 시간, 에러 메시지 표시 |
| 실행 기록 | 완료된 실행은 DB에 저장, 이후 조회 가능 |

### F3. 3D 시각화
워크플로우의 실행 흐름을 3D 공간에서 시각적으로 표현한다.

| 항목 | 설명 |
|------|------|
| 노드 배치 | 2D 에디터의 노드 구조를 3D 공간에 자동 매핑 |
| 데이터 흐름 | 노드 간 연결을 따라 파티클이 이동하는 애니메이션 |
| 상태 이펙트 | 실행 중: 발광, 성공: 녹색 펄스, 실패: 붉은 이펙트 |
| 카메라 조작 | 마우스로 회전, 줌, 팬 |
| 동기화 | 2D에서 노드 선택 시 3D 카메라가 해당 노드로 이동 |

### F4. 워크플로우 관리
워크플로우를 저장, 불러오기, 버전 관리한다.

| 항목 | 설명 |
|------|------|
| 저장/로드 | 워크플로우를 이름으로 저장하고 목록에서 불러오기 |
| 버전 관리 | 저장 시 스냅샷 생성, 이전 버전으로 롤백 가능 |
| 내보내기 | 워크플로우를 JSON으로 내보내기/가져오기 |

### F5. AI 노드 (선택 기능)
LLM API를 워크플로우에 통합한다.

| 항목 | 설명 |
|------|------|
| API 키 | 사용자가 설정 화면에서 본인의 API 키 입력 |
| LLM Prompt 노드 | 이전 노드의 출력을 프롬프트에 삽입하여 LLM 호출 |
| 키 미입력 시 | AI 노드만 비활성, 나머지 워크플로우는 정상 동작 |

## 3. 노드 상세 정의

### 3.1 입력 노드

#### HTTP Trigger
- **역할**: 워크플로우 실행의 시작점. 사용자가 "실행" 버튼을 클릭하면 트리거됨
- **설정**: 없음 (자동 트리거)
- **출력**: `{ triggeredAt: string, workflowId: string }`

#### Webhook (Phase 2)
- **역할**: 외부 HTTP 요청을 수신하여 워크플로우 시작
- **설정**: 엔드포인트 경로, 허용 메서드(GET/POST)
- **출력**: `{ headers: object, body: object, query: object }`

#### Cron (Phase 2)
- **역할**: 지정된 스케줄에 따라 워크플로우 자동 실행
- **설정**: cron 표현식 (예: `*/5 * * * *`)
- **출력**: `{ scheduledAt: string }`

### 3.2 처리 노드

#### API Call
- **역할**: 외부 REST API를 호출하고 응답을 반환
- **설정**:
  - URL (필수)
  - Method: GET / POST / PUT / DELETE
  - Headers: key-value 쌍
  - Body: JSON 에디터 (POST/PUT 시)
  - 타임아웃: 초 단위 (기본 30초)
- **입력**: 이전 노드의 출력을 `{{data.field}}` 템플릿으로 URL/Body에 삽입 가능
- **출력**: `{ status: number, headers: object, data: object }`
- **에러**: HTTP 에러 시 노드 실패 처리, 상태 코드와 응답 본문 로그에 표시

#### Script
- **역할**: JavaScript 코드를 실행하여 데이터를 가공
- **설정**:
  - 코드 에디터 (Monaco Editor)
  - 입력 변수: `input` (이전 노드의 출력)
  - 반환: `return` 문으로 출력 데이터 반환
- **입력**: 이전 노드의 출력이 `input` 변수로 주입
- **출력**: `return` 문의 반환값
- **제한**: 실행 시간 10초 제한, `fetch`/`setTimeout` 등 비동기 API 사용 불가

```javascript
// 예시: API 응답에서 이름만 추출
const names = input.data.users.map(u => u.name);
return { names, count: names.length };
```

#### DB Query (Phase 2)
- **역할**: SQLite에 쿼리를 실행
- **설정**: SQL 쿼리 에디터, 파라미터 바인딩
- **출력**: `{ rows: object[], changes: number }`

### 3.3 분기 노드

#### 조건문 (If/Else)
- **역할**: 조건에 따라 두 갈래로 흐름을 분기
- **설정**:
  - 필드 경로 (예: `input.status`)
  - 연산자: ==, !=, >, <, >=, <=, contains, exists
  - 비교값
- **출력 핸들**: `true` / `false` 두 개의 출력 포트
- **동작**: 조건이 참이면 `true` 포트로, 거짓이면 `false` 포트로 데이터 전달

#### 스위치 (Phase 2)
- **역할**: 값에 따라 N개 갈래로 분기
- **설정**: 분기 조건 목록 + default
- **출력 핸들**: 조건 수 + 1(default)개의 출력 포트

#### 병렬 (Phase 2)
- **역할**: 연결된 모든 다음 노드를 동시에 실행
- **설정**: 없음
- **출력**: 입력 데이터를 모든 출력 포트에 복사

### 3.4 AI 노드 (Phase 2)

#### LLM Prompt
- **역할**: LLM API를 호출하여 텍스트 생성/분석
- **설정**:
  - 프롬프트 템플릿 (텍스트 에디터, `{{input.field}}` 삽입 가능)
  - 모델 선택
  - Temperature, Max Tokens
- **입력**: 이전 노드의 출력이 템플릿 변수로 주입
- **출력**: `{ text: string, usage: { prompt_tokens, completion_tokens } }`
- **전제**: 설정 화면에서 API 키가 입력되어 있어야 함

### 3.5 시각화 노드

#### 로그 출력
- **역할**: 데이터를 하단 로그 패널에 텍스트로 출력
- **설정**: 라벨 (로그 식별용)
- **입력**: 어떤 데이터든 수신
- **동작**: 하단 패널에 JSON 포맷으로 표시

#### 3D 차트 (Phase 2)
- **역할**: 데이터를 3D 뷰포트에 바/파이 차트로 렌더링
- **설정**:
  - 차트 타입: bar / pie
  - 데이터 매핑: label 필드, value 필드
- **입력**: 배열 형태의 데이터
- **동작**: 3D 뷰포트에 차트 오브젝트 생성

#### 3D 클러스터 (Phase 3)
- **역할**: 데이터 포인트를 3D 공간에 클러스터링하여 배치
- **설정**: x/y/z 축 매핑 필드, 색상 매핑 필드
- **입력**: 배열 형태의 다차원 데이터
- **동작**: 3D 뷰포트에 구체 클러스터 생성

### 4.2 패널 상세

#### 상단 툴바
| 요소 | 동작 |
|------|------|
| 워크플로우명 | 클릭 시 인라인 편집 |
| 저장 버튼 | 현재 워크플로우를 DB에 저장 (Ctrl+S) |
| 실행 버튼 | 워크플로우 실행 시작 (Ctrl+Enter) |
| 설정 버튼 | 설정 모달 열기 (API 키, 테마 등) |

#### 노드 팔레트 (좌측)
- 카테고리별 접이식 목록
- 각 노드에 아이콘 + 이름 표시
- 드래그하여 캔버스에 추가
- 검색 필터

#### 2D 에디터 (중앙)
- React Flow 캔버스
- 노드: 카테고리별 색상 구분, 상태 표시 (아이콘/테두리)
- 엣지: 애니메이션 점선 (실행 중일 때)
- 우클릭 컨텍스트 메뉴: 복사, 삭제, 실행 시작점 지정

#### 3D 뷰포트 (우측)
- 기본: 워크플로우 구조를 3D로 매핑한 뷰
- 실행 시: 파티클 흐름 애니메이션
- 마우스 조작: 좌클릭 드래그(회전), 우클릭 드래그(팬), 휠(줌)
- 뷰 전환 버튼: 흐름 모드 / 결과 모드

#### 하단 패널
- **탭 구성**: 로그 | 노드 설정 | 실행 결과
- **로그 탭**: 타임스탬프 + 노드명 + 메시지, 성공/실패 색상 구분
- **설정 탭**: 선택된 노드의 설정 폼 (노드 타입별 동적 생성)
- **결과 탭**: 선택된 노드의 입출력 데이터 JSON 뷰

### 4.3 리사이즈/토글
- 2D/3D 영역 사이 드래그로 비율 조절
- 3D 뷰포트 토글 버튼 — 접으면 2D 에디터가 전체 너비 사용
- 하단 패널 토글 — 접으면 에디터 영역 확장
- 노드 팔레트 토글 — 접으면 아이콘만 표시

## 5. 사용자 시나리오

### 시나리오 1: API 데이터 가공 워크플로우

> 외부 API에서 사용자 목록을 가져와 필터링한 뒤 결과를 확인한다.

1. 노드 팔레트에서 **HTTP Trigger** 드래그 → 캔버스에 배치
2. **API Call** 노드 추가, URL에 `https://jsonplaceholder.typicode.com/users` 입력
3. **Script** 노드 추가, 코드 작성:
   ```javascript
   const activeUsers = input.data.filter(u => u.id <= 5);
   return { users: activeUsers, count: activeUsers.length };
   ```
4. **로그 출력** 노드 추가, 라벨: "필터링 결과"
5. 노드를 순서대로 연결: Trigger → API Call → Script → 로그
6. **실행 버튼** 클릭
7. 3D 뷰포트에서 파티클이 노드를 따라 이동하는 애니메이션 확인
8. 하단 로그 패널에서 필터링된 사용자 목록 확인

### 시나리오 2: 조건 분기 워크플로우

> API 응답 상태에 따라 다른 처리를 수행한다.

1. **HTTP Trigger** → **API Call** 연결
2. **조건문** 노드 추가, 조건: `input.status == 200`
3. **true** 포트 → **Script** (데이터 가공) → **로그** ("성공")
4. **false** 포트 → **로그** ("실패")
5. 실행 시 3D 뷰포트에서 분기점에서 파티클이 갈라지는 연출 확인

### 시나리오 3: AI 분석 워크플로우 (Phase 2)

> API로 가져온 텍스트를 LLM으로 분석하고 결과를 3D 차트로 시각화한다.

1. **HTTP Trigger** → **API Call** (뉴스 API) → **LLM Prompt** (감성 분석)
2. **Script** (결과 파싱) → **3D 차트** (긍정/부정/중립 비율)
3. 실행 결과가 3D 뷰포트에 바 차트로 렌더링됨

## 6. 데이터 모델

### workflows 테이블
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | TEXT (UUID) | PK |
| name | TEXT | 워크플로우 이름 |
| description | TEXT | 설명 (선택) |
| graph | JSON | 노드/엣지 구조 데이터 |
| version | INTEGER | 버전 번호 |
| created_at | DATETIME | 생성 일시 |
| updated_at | DATETIME | 수정 일시 |

### workflow_versions 테이블 (Phase 2)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | TEXT (UUID) | PK |
| workflow_id | TEXT | FK → workflows |
| version | INTEGER | 버전 번호 |
| graph | JSON | 해당 버전의 노드/엣지 스냅샷 |
| created_at | DATETIME | 스냅샷 생성 일시 |

### executions 테이블
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | TEXT (UUID) | PK |
| workflow_id | TEXT | FK → workflows |
| status | TEXT | pending / running / success / error |
| started_at | DATETIME | 실행 시작 |
| finished_at | DATETIME | 실행 종료 |
| duration_ms | INTEGER | 총 소요 시간 |

### execution_nodes 테이블
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | TEXT (UUID) | PK |
| execution_id | TEXT | FK → executions |
| node_id | TEXT | 노드 ID |
| node_type | TEXT | 노드 타입 |
| status | TEXT | idle / running / success / error / skipped |
| input_data | JSON | 입력 데이터 |
| output_data | JSON | 출력 데이터 |
| error_message | TEXT | 에러 메시지 (실패 시) |
| started_at | DATETIME | 노드 실행 시작 |
| finished_at | DATETIME | 노드 실행 종료 |
| duration_ms | INTEGER | 소요 시간 |

### SSE 이벤트 형식

```
event: node-status

event: node-error
data: { "nodeId": "abc", "status": "error", "error": "Connection refused" }

event: execution-complete
data: { "executionId": "xyz", "status": "success", "duration": 1250 }
```

## 8. 비기능 요구사항

### 성능
- 노드 100개 이하의 워크플로우에서 2D 에디터 60fps 유지
- 3D 뷰포트 30fps 이상 유지 (파티클 1000개 기준)
- 워크플로우 실행 시 노드 상태 업데이트 지연 500ms 이내

### 호환성
- 데스크톱 브라우저: Chrome, Firefox, Safari, Edge (최신 2개 버전)
- WebGL 2.0 지원 브라우저 필수
- 모바일: 뷰 전용 (편집 불가), 3D 품질 자동 하향

### 접근성
- WebGL 미지원 시 3D 뷰포트 비활성 + 2D 에디터만 동작
- 모션 감소 설정 (prefers-reduced-motion) 시 파티클 애니메이션 비활성

### 보안
- Script 노드: 샌드박스 환경에서 실행 (eval 대신 Function 생성자 + 제한)
- API 키: 서버 메모리에만 보관, 클라이언트에 노출하지 않음
- 사용자 입력 검증: SQL 인젝션, XSS 방지
